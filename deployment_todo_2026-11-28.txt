[ ] 1.2 Decide on Cloud Run ingress auth vs. app-level auth (CONFLICT)
      - ci_cd.yml deploys with --no-allow-unauthenticated. That makes Cloud Run
        IAM require a Google identity token in the Authorization header, BEFORE
        the request reaches Express.
      - The app ALSO expects "Authorization: Bearer <MCP API key or OAuth JWT>".
        Both cannot use the same header, so Claude Code would get 401/403 from
        Google and never reach requireAuth.
      - The live service currently allows unauthenticated access (probes got 200),
        and app-level auth protects /mcp.
      - Recommended: use --allow-unauthenticated and let middleware/auth.js
        handle auth. Update ci_cd.yml to match.
        (Alternative: keep IAM and put a proxy in front. That's more complex.)

5. BREAKING CHANGES / COMPATIBILITY
==========================================================================================

[ ] 5.1 Legacy SSE clients change auth method
      - Old build: /sse and /messages used the "x-api-key" header.
      - New build: they require "Authorization: Bearer <key>".
      - Any existing client (agents in lab/agents, scripts, other machines)
        using x-api-key will start getting 401. Update them or add temporary
        x-api-key support to requireAuth.

[ ] 5.2 Legacy SSE doesn't work reliably on multi-instance Cloud Run
      - The sessions Map is in memory. If Cloud Run scales to more than one
        instance, the POST /messages can land on a different instance than the
        GET /sse and return "Session not found".
      - Either set --max-instances=1 or --session-affinity, or deprecate SSE and
        use only /mcp (which is stateless and fine to scale).

[ ] 5.3 The rate limiter key changes
      - The unused `limiter` in http_server.js keys on x-api-key. It is defined
        but never applied (only globalLimiter is used). Remove it or key it on
        the Bearer token.
      - With 'trust proxy' = 1, Cloud Run's front end supplies X-Forwarded-For,
        so per-IP limiting should work. Verify it after deploying.
